У цій лабораторній роботі реалізовано REST API веб-застосунок для керування користувачами чергуваннями та повідомленнями до чергувань. Користувач може створювати нові записи користувачів, чергувань та повідомлень переглядати список усіх записів отримувати окремі записи за ID оновлювати існуючі записи та видаляти їх. Також реалізовано отримання повідомлення разом із пов’язаним чергуванням

Дані зберігаються у SQLite базі даних. Реалізовано зв’язки між таблицями users duties та duty_messages

Відповіді сервера повертаються у форматі JSON

1 Запуск проєкту

Відкрити папку backend та виконати команди:

npm run dev

Після запуску у консолі має з’явитися повідомлення:

Server running on http://localhost:3000
DB schema initialized

Проєкт буде доступний за адресою:

http://localhost:3000

2 Ініціалізація бази даних

При запуску проєкту автоматично:

створюються таблиці якщо вони не існують
ініціалізується структура бази даних

Також доступний seed який заповнює базу тестовими даними:

користувачі
чергування
повідомлення

Seed очищає таблиці перед заповненням новими даними

3 API Endpoints
Users

POST /users - створення користувача
GET /users - отримати всіх користувачів
GET /users/id - отримати користувача за ID
PUT /users/id - оновити користувача
DELETE /users/id - видалити користувача

Duties

POST /duties - створення чергування
GET /duties - отримати всі чергування
GET /duties/id - отримати чергування за ID
PUT /duties/id - оновити чергування
DELETE /duties/id - видалити чергування

Messages

POST /messages - створення повідомлення
GET /messages - отримати всі повідомлення
GET /messages/id - отримати повідомлення за ID
PUT /messages/id - оновити повідомлення
DELETE /messages/id - видалити повідомлення

4 Cтатуси

201 Created - успішне створення запису
200 OK - успішне отримання даних
204 No Content - успішне видалення

5 Додатки

Логування:
Усі HTTP запити логуються в консоль з методом URL та статусом відповіді

SQLite база даних:
Дані зберігаються у файлі бази даних та не зникають після перезапуску сервера

Зв’язки між таблицями:
users → duties → duty_messages
